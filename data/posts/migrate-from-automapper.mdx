# Replacing AutoMapper with Custom Extension Methods in .NET

In our case, we had a generic service `BaseFileService<TModel, TEntity>` that saves files. Each file type uses a
different model and entity.

  using Microsoft.AspNetCore.Mvc;
  using YourProject.Services;
  using YourProject.Entities;

  namespace YourProject.Controllers
  {
  [ApiController]
  [Route("api/[controller]")]
  public class A1Controller : ControllerBase
  {
    private readonly A1Service _service;

          public A1Controller(A1Service service)
          {
              _service = service;
          }

          [HttpGet]
          public IActionResult GetAll()
          {
              var data = _service.GetAll();
              return Ok(data);
          }

          [HttpGet("{id:guid}")]
          public IActionResult GetById(Guid id)
          {
              var entity = _service.GetById(id);

              {
                  return NotFound();
              }

              return Ok(entity);
          }
      }
  }

## 🎯 Solution: Custom Extension Methods

We decided to create one static mapping file for each model/entity pair, for example `ClientFileModel` and `ClientFileEntity`.

Example: `ClientFileMappingExtensions.cs`:

```csharp
public static class ClientFileMappingExtensions
{
    public static ClientFileModel ToModel(this ClientFileEntity entity)
    {
        if (entity == null) return null;

        return new ClientFileModel
        {
            Id = entity.Id,
            File = null, // we don't map the file itself
            Status = entity.Status,
            CreatedBy = entity.CreatedBy,
            CreateDate = entity.CreateDate,
        };
    }

    public static ClientFileEntity FromModel(this ClientFileModel model)
    {
        if (model == null) return null;

        return new ClientFileEntity
        {
            Status = model.Status,
            CreatedBy = model.CreatedBy,
            CreateDate = model.CreateDate
        };
    }
}
```

## 💡 Delegates in `BaseFileService`

To keep our service generic, we added two delegates in the constructor:

```csharp
private readonly Func<TModel, TEntity> _fromModel;
private readonly Func<TEntity, TModel> _toModel;

public BaseFileService(
    Func<TModel, TEntity> fromModel,
    Func<TEntity, TModel> toModel,
    ...
)
{
    _fromModel = fromModel;
    _toModel = toModel;
}
```

Then in `ClientFileService` we use those mapping methods:

```csharp
public ClientFileService(...)
    : base(ClientFileMappingExtensions.FromModel, ClientFileMappingExtensions.ToModel, ...)
{ }
```

## 🛠️ How it works in the service

```csharp
public async Task<TModel> SaveFile(TModel file)
{
    if (file == null)
        throw new ArgumentNullException(nameof(file));

    if (file.File.Length > _appSettings.MaxUploadFileSize)
        throw new ArgumentException("File too large.");

    var fileEntity = _fromModel(file);

    var pathData = await _filePathGenerator.GetPathToFile(ApplicationId, Path.GetExtension(file.File.FileName));
    fileEntity.PointerToSource = pathData.FileName;

    await _networkFileService.UploadFile(new FileLocation(pathData), file.File.OpenReadStream());

    var savedEntity = await _baseFileRepository.AddFile(fileEntity, _currentUserService.CurrentUserId());

    return _toModel(savedEntity);
}
```

## 🧹 Conclusion

By removing AutoMapper, we now have full control over mapping logic. This is a good solution when your project has
specific models and you want to keep things simple, readable, and testable.
